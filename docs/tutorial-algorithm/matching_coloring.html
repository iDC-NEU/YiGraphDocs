matching_coloring

Matching & Coloring 匹配与着色算子集

算子类别：Matching & Coloring（图匹配、边覆盖、顶点着色与色多项式）

算法数量：10 个

适用阶段：一对一配对、最优撮合、二部图完全匹配、快速匹配、边覆盖、匹配合法性校验、冲突分组、均衡分组、图着色复杂度分析、组合结构分析

产品定位：为“如何无冲突配对 / 如何最优配对 / 如何完成二部图全量匹配 / 如何覆盖所有节点 / 如何在冲突约束下分组 / 如何分析图的着色方案数量”提供匹配、覆盖与着色类算子能力底座。

一、算子集概述​

Matching & Coloring 算子集聚焦于图上的配对优化、覆盖关系、冲突分组与着色结构分析，主要回答以下问题：

  1. 匹配与配对优化

    • 如何从图中选择一组互不冲突的边？
    • 如何最大化配对收益？
    • 如何最小化配对成本？
    • 如何快速生成一个可用匹配方案？

  2. 二部图匹配

    • 如何在二部图中完成低成本全量匹配？
    • 如何处理供需双方、岗位候选人、任务资源之间的配对？
    • 如何快速寻找二部图中的匹配关系？

  3. 边覆盖问题

    • 如何用尽量少的边覆盖所有节点？
    • 如何保证每个对象至少参与一次连接？

  4. 冲突分组与顶点着色

    • 如何给节点分组，使相邻节点不同组？
    • 如何在考试排期、频率分配、资源冲突中生成可用分组？
    • 如何在满足冲突约束的同时，让各组规模尽量均衡？

  5. 着色结构分析

    • 给定图在不同颜色数量下有多少种合法着色方案？
    • 图的冲突复杂度如何用多项式形式表达？

三、通用输入输出约定​

  • 输入 G：NetworkX Graph / DiGraph

    • 匹配类通常适用于无向图
    • 二部图匹配类通常要求输入为 bipartite graph
    • 边覆盖类通常用于无向图
    • 着色类通常基于节点邻接冲突关系建模

  • 常见输入参数

    • weight：边权属性字段名
    • maxcardinality：是否优先最大化匹配边数
    • matching：待校验的匹配集合或映射
    • top_nodes：二部图中指定的一侧节点集合
    • strategy：贪心着色的节点排序策略
    • interchange：是否启用颜色互换优化
    • num_colors：均衡着色使用的颜色数量

  • 常见输出类型

    • 匹配类：set[(u, v), ...] 或 dict[node -> node]
    • 校验类：bool
    • 边覆盖类：set[(u, v), ...]
    • 着色类：dict[node -> color_id]
    • 多项式类：symbolic polynomial / 表达式

四、算子详细说明​

1. max_weight_matching —— 最大权重匹配​

功能说明 在无向加权图中寻找一组互不冲突的边，使匹配边的权重总和最大。

匹配要求：

  • 一个节点最多只能出现在一条匹配边中
  • 任意两条匹配边不能共享端点

产品价值

  • 支持一对一最优撮合
  • 可在收益、偏好、相似度、成交额等指标下寻找高价值配对
  • 适合需要“配对质量最大化”的业务场景

典型场景

  • 岗位与候选人撮合
  • 供需资源匹配
  • 订单与运力撮合
  • 社交 / 协作对象配对
  • 推荐系统中的一对一高价值连接

关键参数

  • weight：边权字段，默认通常为 weight

  • maxcardinality：

    • False：优先最大化总权重
    • True：优先最大化匹配边数，再在同等边数下最大化权重

适用与特性

  • 图类型：无向图
  • 输出：匹配边集合
  • 复杂度：通常为 O(V^3)
  • 适合中小规模高价值配对任务

2. min_weight_matching —— 最小权重匹配​

功能说明 在无向加权图中寻找一组互不冲突的边，使匹配边的权重总和最小。

常用于边权表示：

  • 成本
  • 距离
  • 损失
  • 不匹配程度
  • 风险代价

产品价值

  • 支持一对一约束下的成本最小化
  • 适合资源调度、物流分配、任务指派等优化问题
  • 可将“最小代价配对”转化为图匹配问题

典型场景

  • 物流配送资源配对
  • 任务与执行人分配
  • 供应链成本优化
  • 相似对象两两配对
  • 风险或损失最小化撮合

关键参数

  • weight：边权字段，默认通常为 weight
  • 若边缺失权重，通常会按默认权重处理，可能影响结果解释

适用与特性

  • 图类型：无向图
  • 输出：匹配边集合
  • 复杂度：通常为 O(V^3)
  • 适合成本型一对一配对问题

3. maximal_matching —— 极大匹配​

功能说明 生成一个极大匹配，即在当前匹配结果中，已经无法再加入任何边而不破坏匹配约束。

需要注意：

  • 极大匹配不等于最大匹配
  • 极大匹配只保证“不能再扩展”
  • 不保证边数最多，也不保证权重最优

产品价值

  • 快速得到一组无冲突配对方案
  • 适合对速度要求高、对最优性要求较低的场景
  • 可作为后续优化算法的初始解

典型场景

  • 快速任务分配
  • 在线撮合初步结果
  • 大规模图上的快速可行解
  • 临时排班或临时配对
  • 匹配算法预处理

适用与特性

  • 图类型：无向图
  • 输出：匹配边集合
  • 复杂度：通常为 O(E)
  • 特点：速度快，但不保证全局最优

4. minimum_weight_full_matching —— 最小权重全匹配​

功能说明 在二部图中寻找一个最小权重匹配，使指定一侧节点能够被完整匹配。

它常用于二部图中的“全量指派”问题，例如：

  • 每个任务都要分配到一个资源
  • 每个岗位都要匹配到一个候选人
  • 每个订单都要匹配到一个执行方

产品价值

  • 支持二部图场景下的完整低成本匹配
  • 适合严格要求“某一侧节点全部被覆盖”的指派问题
  • 可用于成本最小化、距离最短化、损失最小化的全量分配

典型场景

  • 任务与人员分配
  • 订单与司机撮合
  • 岗位与候选人匹配
  • 供应商与需求方分配
  • 资源池到任务池的最小成本指派

关键参数

  • G：二部图
  • top_nodes：二部图其中一侧节点集合
  • weight：边权字段，通常表示成本、距离或损失

适用与特性

  • 图类型：二部图
  • 输出：匹配映射或匹配关系
  • 适合“必须覆盖一侧节点”的完整匹配问题
  • 若图中不存在可行完整匹配，可能无法返回有效结果

5. eppstein_matching —— Eppstein 二部图匹配​

功能说明 用于在二部图中计算匹配关系，常用于快速求解二部图最大匹配问题。

它关注的是：

  • 二部图两侧节点之间的可行配对
  • 在不共享端点的约束下，尽可能建立更多匹配边
  • 为覆盖、指派和二部结构分析提供基础匹配能力

产品价值

  • 面向二部图匹配场景
  • 适合快速生成较大规模二部图中的匹配结果
  • 可作为资源分配、关系撮合、边覆盖等能力的底层支撑

典型场景

  • 用户与物品匹配
  • 工人与岗位匹配
  • 任务与机器匹配
  • 供需两侧撮合
  • 二部网络结构分析

适用与特性

  • 图类型：二部图
  • 输出：匹配映射或匹配边关系
  • 适合二部图最大匹配类问题
  • 常作为二部图匹配工具链中的基础算法

6. min_edge_cover —— 最小边覆盖​

功能说明 寻找一组边，使图中的每个节点至少被其中一条边覆盖，并且使用的边数尽可能少。

与匹配不同：

  • 匹配要求节点最多出现一次
  • 边覆盖要求节点至少出现一次
  • 边覆盖允许一个节点出现在多条覆盖边中

产品价值

  • 用最少关系覆盖所有对象
  • 适合构造最小代表性连接子集
  • 可用于“每个节点都要被触达 / 被关联 / 被采样”的任务

典型场景

  • 用最少交易记录覆盖所有账号
  • 用最少关系覆盖所有用户
  • 岗位 / 人员最低参与关系构造
  • 数据抽样中的最小覆盖关系
  • 二部图中的对象覆盖分析

关键参数

  • matching_algorithm：可指定内部最大匹配算法
  • 默认通常基于最大匹配结果构造最小边覆盖

适用与特性

  • 图类型：无向图，常用于二部图
  • 输出：边覆盖集合
  • 复杂度：取决于内部匹配算法
  • 二部图场景下，常见最大匹配算法复杂度约为 O(E√V)

7. is_matching —— 匹配合法性校验​

功能说明 判断给定的匹配结果是否为图中的合法匹配。

合法匹配需要满足：

  • 每条匹配边必须存在于图中
  • 任意两条匹配边不能共享节点
  • 每个节点最多只能参与一次配对

产品价值

  • 可作为匹配结果的前置或后置校验
  • 防止一个对象被重复分配
  • 适合校验人工输入、外部系统返回或模型生成的配对结果

典型场景

  • 校验任务分配结果
  • 校验撮合系统输出
  • 检查是否有人被重复配对
  • 检查配对边是否真实存在
  • 匹配算法测试与结果验证

输入要点

  • matching 可以是边集合或节点映射
  • 若为映射形式，通常需要满足双向一致性，例如 matching[u] == v 且 matching[v] == u

适用与特性

  • 图类型：无向图
  • 输出：bool
  • 复杂度：与匹配规模相关，通常可近似视为线性检查
  • 常与匹配生成类算法搭配使用

8. greedy_color —— 贪心图着色​

功能说明 为图中的每个节点分配颜色编号，使得相邻节点不能使用相同颜色。

基本思想：

  • 按某种顺序遍历节点
  • 为当前节点分配一个与已着色邻居不同的最小可用颜色
  • 最终输出节点到颜色编号的映射

产品价值

  • 将冲突关系转化为分组方案
  • 支持排期、资源分配、频率分配等约束问题
  • 计算快、结果直观、易于产品化展示

典型场景

  • 考试排期
  • 会议 / 任务冲突调度
  • 频率分配
  • 编译器寄存器分配
  • 用户或设备互斥分组
  • 风控对象隔离分组

关键参数

  • strategy：节点着色顺序策略，常见包括：

    • largest_first
    • random_sequential
    • smallest_last
    • independent_set
    • connected_sequential_bfs
    • connected_sequential_dfs
    • saturation_largest_first / DSATUR

  • interchange：是否启用颜色互换优化，用于尝试减少颜色数

适用与特性

  • 图类型：无向图 / 有向图
  • 输出：dict[node -> color_id]
  • 复杂度：通常接近 O(V + E)，具体取决于策略
  • 贪心着色不保证使用最少颜色，但通常效率高、效果稳定

9. equitable_color —— 均衡图着色​

功能说明 在满足相邻节点不同色的前提下，将节点分配到指定数量的颜色中，并尽量保证各颜色组规模均衡。

均衡着色关注两个目标：

  • 相邻节点不能同色
  • 不同颜色组中的节点数量尽量接近

产品价值

  • 在冲突分组基础上进一步控制组规模平衡
  • 适合需要“公平分摊”或“负载均衡”的分组场景
  • 比普通贪心着色更适合资源容量相近的业务任务

典型场景

  • 考试排期中均衡每场人数
  • 任务分组中均衡每组负载
  • 频率 / 信道分配中的均衡使用
  • 用户分桶与实验分组
  • 风控名单分批处理

关键参数

  • num_colors：指定颜色数量
  • 颜色数量需要足够大，否则可能无法满足相邻节点不同色与均衡约束

适用与特性

  • 图类型：通常用于无向图
  • 输出：dict[node -> color_id]
  • 特点：相比 greedy_color，更强调分组规模均衡
  • 适合“冲突约束 + 负载均衡”同时存在的场景

10. chromatic_polynomial —— 色多项式​

功能说明 计算图的色多项式。色多项式用于描述：当可用颜色数量为 k 时，图有多少种合法顶点着色方案。

其中合法着色要求：

  • 相邻节点不能使用相同颜色
  • 每个节点必须分配一个颜色

产品价值

  • 从组合数学角度刻画图的着色复杂度
  • 可分析不同颜色数量下的可行方案规模
  • 适合对冲突网络进行理论分析、结构评估和可行性研究

典型场景

  • 着色方案数量分析
  • 冲突图复杂度评估
  • 排期 / 分组可行性分析
  • 图论教学与研究
  • 小规模图的组合结构分析

适用与特性

  • 图类型：通常用于无向图

  • 输出：色多项式表达式

  • 注意：色多项式计算通常比普通贪心着色成本更高，更适合小规模图或分析型任务

  • 与 greedy_color 的区别：

    • greedy_color 给出一种具体着色方案
    • chromatic_polynomial 描述不同颜色数量下的合法方案数量

五、推荐使用指南​

1. 一对一配对与撮合​

  • 收益最大化：max_weight_matching
  • 成本最小化：min_weight_matching
  • 快速生成可行配对：maximal_matching
  • 校验配对是否合法：is_matching

2. 二部图全量匹配​

  • 二部图最小成本完整匹配：minimum_weight_full_matching
  • 二部图快速匹配：eppstein_matching
  • 岗位 / 任务 / 资源指派：优先考虑 minimum_weight_full_matching

3. 覆盖所有节点​

  • 用最少边覆盖所有节点：min_edge_cover
  • 需要每个对象至少出现一次：min_edge_cover
  • 需要构造最小关系子集：min_edge_cover

4. 冲突分组与排期​

  • 相邻节点不能同组：greedy_color
  • 需要稳定、常用启发式：largest_first
  • 需要更少颜色数：优先尝试 saturation_largest_first / DSATUR
  • 需要组规模尽量均衡：equitable_color

5. 着色复杂度分析​

  • 需要具体分组方案：greedy_color
  • 需要均衡分组方案：equitable_color
  • 需要分析合法着色方案数量：chromatic_polynomial

六、可直接回答的典型问题​

  • “在一对一约束下，如何最大化总收益？”
  • “如何把候选人和岗位做最优匹配？”
  • “如何在成本最低的情况下完成配对？”
  • “给我一个快速的无冲突配对方案。”
  • “这组配对是否合法？有没有人被重复配对？”
  • “如何在二部图中完成最小成本全量匹配？”
  • “如何快速计算二部图中的匹配关系？”
  • “如何用最少关系覆盖所有节点？”
  • “如何保证每个对象至少参与一次连接？”
  • “如何把存在冲突的任务分到不同组？”
  • “如何安排考试，使冲突学生不会出现在同一场？”
  • “如何在分组时保证各组规模尽量均衡？”
  • “不同着色策略下，哪种使用的颜色更少？”
  • “这个冲突图在 k 种颜色下有多少种合法着色方案？”
  • “这个图的色多项式是什么？”
