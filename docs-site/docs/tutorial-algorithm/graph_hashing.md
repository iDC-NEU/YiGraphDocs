# Graph Hashing 图哈希算子集

**算子类别**：Graph Hashing（图哈希、结构指纹与图结构摘要）

**算法数量**：1 个

**适用阶段**：图结构去重、图结构快速比较、图样本索引、子图模式检索、图版本对比、结构指纹生成、图相似性预筛选、图数据缓存与增量计算

**产品定位**：为“这个图的结构指纹是什么 / 两个图是否可能结构一致 / 如何快速做图去重 / 如何为图结构生成可索引的摘要表示”提供图哈希能力底座。

---

## 一、算子集概述

Graph Hashing 算子集聚焦于**为图结构生成稳定、紧凑、可比较的哈希表示**，主要回答以下问题：

1. **图结构指纹生成**

   * 如何把一个图转换为固定长度或紧凑的结构摘要？
   * 如何用哈希值表示图的拓扑结构？
   * 如何为图样本建立可索引、可缓存的结构标识？

2. **图结构快速比较**

   * 两个图的结构是否可能相同？
   * 两个图是否可以先通过哈希值做快速预筛？
   * 在大批量图样本中，如何快速定位结构重复或近似重复的图？

3. **图数据去重与版本对比**

   * 不同来源的图是否存在重复结构？
   * 图结构更新前后是否发生变化？
   * 子图抽取结果是否已经被处理过？

4. **图模式检索与缓存**

   * 如何给子图模式生成可复用标识？
   * 如何为图计算结果建立缓存 key？
   * 如何减少重复计算和重复分析？

## 三、通用输入输出约定

* **输入 `G`**：NetworkX Graph / DiGraph
* **常见输入参数**：

  * `node_attr`：节点属性名，用于将节点属性纳入哈希计算
  * `edge_attr`：边属性名，用于将边属性纳入哈希计算
  * `iterations`：WL 颜色细化迭代次数
  * `digest_size`：哈希摘要长度
* **常见输出类型**：

  * 图哈希字符串：`str`
* **结果解释**：

  * 哈希值相同：两个图可能具有相同或高度一致的结构表示
  * 哈希值不同：两个图在结构或指定属性口径下通常可判定为不同

## 四、算子详细说明

### 1. weisfeiler_lehman_graph_hash —— Weisfeiler-Lehman 图哈希

**功能说明**
基于 Weisfeiler-Lehman 颜色细化思想，为图生成一个结构哈希值。算法会从节点标签或属性出发，反复聚合邻居信息并更新节点表示，最终将图整体结构编码为一个哈希摘要。

**产品价值**

* 为图结构生成稳定的结构指纹
* 支持大批量图样本的快速去重与索引
* 可作为图同构、图相似性或结构匹配前的预筛选步骤
* 支持将节点属性、边属性纳入结构摘要，提高业务语义表达能力

**典型场景**

* 图结构去重
* 子图模式缓存
* 图版本变更检测
* 大规模图样本索引
* 分子图结构指纹生成
* 欺诈团伙结构模式检索
* 工作流 / 流程图结构对比
* 知识图谱局部结构摘要

**关键参数**

* `node_attr`：指定节点属性作为初始节点标签
* `edge_attr`：指定边属性参与邻居聚合
* `iterations`：控制邻居信息传播和结构感知范围
* `digest_size`：控制输出哈希摘要长度

**适用与特性**

* 图类型：有向图 / 无向图
* 输出：图结构哈希字符串
* 特点：计算相对高效，适合批量图结构摘要与快速比较
* 注意：哈希值通常用于快速预筛，不应完全替代严格图同构判定

## 五、推荐使用指南

### 1. 图结构指纹生成

* 为单个图生成结构哈希：`weisfeiler_lehman_graph_hash`
* 为子图、模式图或局部关系圈生成摘要：`weisfeiler_lehman_graph_hash`

### 2. 图结构去重

* 批量计算图哈希值
* 将哈希值相同的图归为候选重复结构
* 对候选结果再结合业务字段或同构算法做精确确认

### 3. 图版本对比

* 对更新前后的图分别计算哈希值
* 哈希值不同通常表示结构或指定属性发生变化
* 哈希值相同可作为结构未明显变化的快速判断依据

### 4. 缓存与索引

* 使用图哈希作为图计算结果缓存 key
* 使用子图哈希作为模式检索或去重索引
* 用于减少重复图分析、重复子图抽取和重复模型计算

### 5. 场景化选型建议

* **想为图生成结构指纹**：`weisfeiler_lehman_graph_hash`
* **想快速判断两个图是否可能相同**：`weisfeiler_lehman_graph_hash`
* **想做大批量图去重**：`weisfeiler_lehman_graph_hash`
* **想给子图模式建立索引**：`weisfeiler_lehman_graph_hash`
* **想判断图结构更新前后是否变化**：`weisfeiler_lehman_graph_hash`
* **想作为图同构判断前的预筛选**：`weisfeiler_lehman_graph_hash`

## 六、工程与使用注意事项

1. **图哈希适合预筛，不等于严格同构证明**
   哈希值相同通常表示两个图在当前哈希口径下高度一致，但仍建议在关键场景中结合 `is_isomorphic` 等算法做精确确认。

2. **节点和边属性会影响哈希语义**
   指定 `node_attr` 或 `edge_attr` 后，哈希不仅反映拓扑结构，也会反映对应属性。属性缺失、类型不一致或命名不统一，都会影响结果。

3. **iterations 决定结构感知范围**
   迭代次数越多，节点能聚合到越远邻域的信息；但迭代次数过大也会增加计算成本，并可能带来过度平滑式的摘要效果。

4. **digest_size 影响摘要长度与碰撞风险**
   较大的摘要长度通常能降低碰撞概率，但也会增加存储长度。大规模索引场景可根据碰撞容忍度选择合适值。

5. **图预处理要保持一致**
   做版本对比、去重或批量索引时，应保持节点属性、边属性、方向性、多重边处理方式和参数配置一致，否则哈希结果不具备可比性。

6. **有向图与无向图口径不同**
   同一批边如果按有向图和无向图分别计算，哈希语义不同。需要根据业务关系是否具有方向性选择图类型。
